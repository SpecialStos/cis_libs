# cis_libs v1

The specification of the cis_libs v1 surface: what is frozen, what is
deprecated, the bars every release must meet, and the open calls the owner
makes. Written 2026-10-24 on branch `cis-libs-a-grade` for the overnight run
described in the workspace's `research/handoffs/2026-10-24-cis_libs.md`, built
to `research/handoffs/2026-10-24-boundary.md`, and checked against the ox_lib
rival brief `research/rivals-ox_lib.md` (ox_lib v3.40.3).

## 1. What v1 is

- **v1 is contract major `api = 1`.** The frozen surface is exactly the
  `exports`, `functions`, `events` and `modules` blocks of `api.lua`. Section 9
  below is generated from that file by `npm run gen-types`, and
  `npm run gen-types:check` fails when it is stale, so this document and the
  code cannot disagree.
- **Frozen means:** no name in section 9 is removed, renamed, or changes its
  parameters or the meaning of its returns while `api = 1`. A new entry is
  additive and carries its own `since`. A removal is announced first as a
  deprecation with an `until`, and it lands only with `api = 2`.
- **The product version** in `api.lua`, `fxmanifest.lua` and `package.json` is
  still `1.0.0`. Everything this branch adds is `since = '1.1.0'`, so the next
  release of this branch is 1.1.0 (see Decisions, D7).
- **cis_libs is a library.** It names no framework, inventory, target, doorlock
  or database, it depends on nothing, and it has no `provide`. The pieces that
  do name one are deprecated (section 3) and leave in 2.0.0, to cis_bridge and
  cis_core.

### 2.1 What v1 keeps that names a capability

- **The generic capability registry** (`RegisterCapability`,
  `UnregisterCapability`, `GetCapability`, `CallCapability` and the rest).
  The boundary file proposes dropping it. v1 keeps it, because the `ui`,
  `discord` and `security` slots still route through it and because removing
  a registry is the hard-to-reverse choice (D1).
- **`ui`** (notify, text UI, progress, confirm, input). The built-in NUI is a
  library primitive. cis_bridge may register a provider that routes notify to
  the server's own system.
- **`discord`**. The slot names no third-party resource. cis_libs only
  forwards log lines to it (`server/proxy.lua`, `server/logging.lua`); it holds
  no webhook queue and makes no HTTP call of its own. The provider is external
  (D10).
- **`security`**. The slot is the hook a host uses to act on a security report
  (`SecurityReport`). The boundary file moves `security.drop` to cis_core;
  v1 keeps the generic slot, and cis_core is free to be its provider (D2).
- **`Notify`** (and its `framework.ShowNotification` route, which is a slot
  method, not an export). It has a built-in fallback that needs no framework,
  so it stays and never warns, even though it routes through the `framework`
  slot today. What it routes through after 2.0.0 is D11.
- **`PublishPlayerLoaded` and `PublishJobUpdate`** and their events
  `cis_libs:playerLoaded` and `cis_libs:jobUpdated`. They are a generic
  publish seam, not detection (D3).

## 3. Deprecated in 1.1.0, removed in 2.0.0

Every item below still works unchanged until 2.0.0. Each deprecated slot and
export logs one warning per calling resource and per name (`shared/registry.lua`
`CisRegistry.warnDeprecated`), and forgets the caller when that resource stops.
`GetKnownTargets`, `RequestInventorySync`, `RequestLockDoors` and
`RequestUnlockDoors` warn under their own names, so they warn even with no
provider behind them. Calls cis_libs makes into its own slots never warn.

Three kinds of item are deprecated in silence, by design: the server handler
for `cis_libs:server:inventorySync` (its sender is a player, not a resource to
name; `RequestInventorySync` warns instead), the config keys (read once at
boot, with no caller), and `shared/detect.lua` (internal; the exports in front
of it warn).

`api.lua` marks each deprecated export and event `deprecated = true` with
`until = '2.0.0'` and its replacement in `use`. The types mark all 32 exports
and the 18 `Cis.*` proxies that forward to them `---@deprecated` (50 in all),
both-realm exports included.

## 5. Against ox_lib

From `research/rivals-ox_lib.md` section 5, pinned to ox_lib v3.40.3 at
`1f87a022`.

- **Match.** cis_libs already covers every ox_lib module a product uses
  (callbacks, zones, points, commands, keybinds, the UI kit, streaming,
  raycast, cache, markers, scaleform, DUI, statebag handlers, locale).
- **Beat, already.** Callback replies are bound to the asked player, with an
  unguessable key and a 10 s default; NUI inputs are judged in Lua; zones and
  points refuse degenerate and far-away shapes; the loader has no globals and
  an explicit module list.
- **Gaps a replacing resource needs**, all additive, none in the frozen v1
  set yet: `checkDependency`, the remaining `math` helpers, a server
  `triggerClientEvent` for many targets, `loadJson`, `setClipboard`,
  server-side `setVehicleProperties`, and server `getClosestPlayer` /
  `getNearbyPlayers`. They ship as `since = '1.1.0'` additions only after
  each has its own tests (D6).
- **Must beat, planned** (brief section 5.2), each a 1.1.0 addition with its
  own tests, none frozen yet: a server-side `Cis.statebag.set` with a
  validator and a strict-mode boot warning; progress props validated on
  receipt; zone regression tests for a teleport out, a removal mid-iteration
  and a repeated `onEnter`; an `init.lua` boot self-check pinned in CI; and
  documented `Cis.ready`. Progress names any that shipped.
- **Leave out:** OO entity wrappers that replicate state bags from the client,
  ACL policy, third-party logger sinks, admin tooling, global monkey patches,
  and a phone-home version check that is on by default.

## 6. Non-goals

- No framework, inventory, target, doorlock or database knowledge after 2.0.0.
- No feature added only for parity: an addition must be one a product needs.
- No third-party service integration. The only outbound call cis_libs makes
  is the version check in `server/version.lua`, off by default
  (`CheckVersion = false`).
- No client-authoritative state: the client asks, the server decides.

## 7. Decisions for the owner

Each was decided overnight with the option easiest to reverse. Change any of
them by saying so; nothing below is hard to undo yet.

- **D1. The generic capability registry stays in v1.** The boundary file
  proposes dropping it. Removing it later is one deprecation; adding it back
  after products stop calling it would be a new API.
- **D2. The `security` slot stays in cis_libs.** The boundary file moves
  `security.drop` to cis_core. The slot is generic (act on a report); cis_core
  can be its provider without cis_libs naming it.
- **D3. `PublishPlayerLoaded`, `PublishJobUpdate` and their events stay.**
  DOCUMENTATION says framework events belong to cis_core. They name no
  framework, and any bridge target may call them, not only cis_core; deprecating them is one line if you disagree.
- **D4. Deprecated, not deleted.** Deletion waits for the bridge's
  `bridge-off-slots` line and ships as 2.0.0 with `api = 2` in one commit.
- **D5. Toast versus Notify.** v1 keeps both names: `Notify` is the stable
  export with the built-in fallback; the `ui` toast is the NUI primitive it
  falls back to.
- **D6. ox_lib parity gaps are 1.1.0 additions, not v1 freezes.** Section 5's
  list waits for a product that needs each one, unless the run has time to
  ship one with tests; any that shipped are listed in Progress.
- **D7. Version story.** The branch's additions say `since = '1.1.0'` while the
  manifest says 1.0.0. The manifest is bumped at release, not tonight, so no
  build in the wild claims a version that was never released.
- **D8. `SetConfig` stays first-caller-wins.** Changing who may reconfigure the
  library is a security decision with live-server effects; Phase 3 hardens the
  merge, not the policy.
- **D9. Licence, history and CI secrets stay as they are.** The licence text,
  the historic commits that carry an AI co-author line, the
  `FIVEM_LICENSE_KEY` repository secret and its rotation, and opening a PR to
  `main` so CI runs there are all owner actions. None was touched.
- **D10. No webhook queue in cis_libs.** The `discord` slot stays and cis_libs
  forwards to it, but the queue and the HTTP call belong to whoever provides
  the slot. Shipping a queue later is additive.
- **D11. What `Notify` routes through in 2.0.0** is decided in the 2.0.0
  commit. The default plan: the `ui` slot, then the built-in feed, with
  `Cis.framework.notify` kept as an alias so no consumer breaks.
- **D12. The idle bar tolerates 0.01 to 0.02 ms** on the client, as the
  workspace skill's invariant 4 does (idle 0.00 to 0.02 ms). The server bar is
  0.05 ms per frame. Tightening either is a one-line change here.
- **D13. NUI replies carry no reason to the page.** A reason would tell a
  forged page which check it failed. Adding a `reason` field later is
  additive; taking one away would not be.
- **D14. `SetConfig`'s `security` is merged over the defaults.** 1.0.0
  documented "replaces outright", and a supplier that left out `DropPlayer`
  turned kicks off without saying so. The merge keeps the safe default; a
  supplier that wants kicks off says `DropPlayer = false`. Going back is a
  one-line change in `server/proxy.lua` (mutation M672 is that line).
- **D15. `mathx.clamp` refuses reversed bounds and a NaN value** with
  `nil, reason`, as `interp.clamp` and `validate.clamp` already did. 1.0.0
  swapped reversed bounds silently, so a caller with `lo > hi` got a number
  from inside a range it never asked for. A caller that does arithmetic on the
  result now raises on that input instead of using a wrong value. No module in
  cis_libs calls it. Going back to the swap is a two-line change in
  `shared/util/mathx.lua`.
- **D16. `locale.t` runs the format whenever any argument is given**, a table
  of named values alone included. So `%%` prints as one `%` in every call that
  passes an argument, and a phrase with a lone `%` logs a warning once and
  prints with its named values filled in. With no argument the phrase is
  returned as written, as before.
- **D17. The deprecated slots are not removed yet, and there is no 2.0.0
  tonight.** cis_bridge wrote `bridge-off-slots cis_bridge@4dff26a` at 09:06,
  but at that commit `server/lib.lua` line 37 still forwards the `Db*` exports
  and `shared/lib/shim.lua` lines 356 and 403 call `DbQuery` and
  `DbTransaction` through them. cis_core `main` still calls
  `RegisterCapability('inventory', ...)` (`client/inventory.lua` line 113),
  `RegisterCapability('framework', ...)` (`framework/framework_client.lua`
  line 413) and `DetectFramework` (`framework/framework_client.lua` line 53,
  `framework/framework_server.lua` line 166). Removing the slots now would
  break both. The removal commit (section 3) waits until neither repo calls
  them; keeping them costs one warning per calling resource.
- **D18. A context menu option's `event` must start with the registering
  resource's name and a colon** (`myres:open`), and reserved names are
  refused. A menu could otherwise fire any other resource's client event on
  the player's behalf. `serverEvent` is unchanged: the server validates it.
  This breaks ox_lib parity for a bare event name; the ox_lib way that still
  works is `onSelect`. Relaxing it is one check in `client/context.lua`.
- **D19. Radial and context ids are owned by the resource that registered
  them.** Another resource cannot replace, update or remove them. Before this,
  a second resource registering the same id silently took the menu over.
- **D20. Progress-bar props are local entities**, created with networking off.
  A networked prop costs a server entity per player per bar, and a script
  that never cleaned one up left it in the world for everyone. The price:
  other players do not see the prop. A product that wants them to creates a
  networked prop itself. Going back is one argument in
  `client/interface/progress.lua`.
- **D21. NUI defaults and caps.** `accent-fg` defaults to `#0b1220`, so text on
  the accent colour is readable when a theme sets only `accent`. A message
  over 1 MiB (`MAX_MESSAGE`, `client/interface/nui.lua`) is logged and not
  sent, because CEF stalls on it. The page's error and warn reports are
  limited to 10 per kind per 10 seconds (`REPORT_BURST`), so a broken or
  forged page cannot flood the server console. Each is one constant.
- **D22. Utility edge answers.** `weightedPick` picks an infinite weight
  whenever one is present. `random` refuses bounds past 2^53, where a float
  cannot hold every integer. `id.draw` caps a count at 65536.
  `validate.defaults` fails when a nested schema fails, instead of dropping
  the field silently. `normaliseName` refuses a letter or digit as the separator.
  Each answer is `nil, reason` or `false, reason`, never a wrong value.
- **D23. `api.lua` carries an `unreleased = '1.1.0'` field** so the validator
  (E014) can accept `since = '1.1.0'` entries while the manifest says 1.0.0
  (D7). The field is removed in the version-bump commit.
